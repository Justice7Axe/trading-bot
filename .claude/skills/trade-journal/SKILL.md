# 📓 매매일지 · 복기 노트

> 사용자 2026-11-06: "항상 각 매매에 대한 매매일지를 작성하고 있지?" → "매매일지를 보고 복기하면서 매매 전략을 개선해야 돼" → "과거 것도 매매일지 작성하고 복기 노트 만들어줘, 매매일지 및 복기노트 작성 스킬도 만들어 활용해줘".

일지는 **자동**(표·로그에서 사실만 모음), 복기 노트는 **사람이 읽고 쓰는 것**(왜·배운 점·개선 후보)으로 나눈다.

## 1. 매매일지 구성 (`kiwoom_trading/execution/journal.py`)
1. **머리말** — 09:10(09:20 재판정) 시장 분위기 판정(강한 상승장 / 상승·하락 흐름 보통 날 / 강한 하락장, 대금 상위 중앙값·코스피 %·20일 변동성 배수), 큰 흐름(코스피 52주 고점 대비), 코스피·코스닥 마감 등락(`data/index.duckdb` idx_daily), 간밤 미국(`us_overnight`). 보통 날은 `market_regime` 표에 안 남아 스캐너 로그 '시장 분위기 판정' 줄에서 읽음.
2. **🔴 실전 매매 한 건씩** (그날 산 것·판 것·들고 있는 것, `real_trades`) — 매매 이름(번호 옆 이름 필수) · 종목 · 포착 이유(`buy_signals.reason`, 📕 는 가상 장부 note) · 매수 시각/가격/수량 · 매도 시각/가격/이유 · 손익(원·%, 비용 포함) · 보유 중이면 그날 정규장 종가 평가(나중에 만들면 '이후 매도' 결과도) · **규칙대로였나**(손절·익절·다음 날 시초 = 규칙대로, '직접 매도'·'사용자' = ⚠️ 직접 매도) · 1분봉 차트 `data/journal/YYYYMMDD/<code>.png`(KRX, 장 밖 매매·없으면 통합 AL; 매수▲·매도▼·매수가·손절선·익절가).
3. **⏭ 실전 못 산 신호** — 로그 '실전 안 삼'(엄격 선정 등 규칙상 대상 아님)·'실전 못 삼'(예수금·추격·이미 많이 오름) + 신호가 대비 그날 종가(4️⃣ 역행 강세 종가·🌙 종가 재돌파는 다음 날 시가) → 놓친 기회 / 피한 손실.
4. **🟢 모의 · 🟣 가상** — 매매(kind·장부 book)별 그날 끝난 건수·이긴 수·손익 합·들고 넘김, ±5% 이상·직접 매도만 한 줄씩.
5. **📝 복기 칸 (자동 표시)** — 손절된 실전, ⚠️ 직접 매도 + '규칙대로였으면'(그날 남은 1분봉에서 손절 먼저·익절, 아니면 다음 날 09:00 시가로 다시 계산해 차이), 손절선 1% 안까지 갔다 살아난 것, 놓친 신호 중 +5%↑, 최근 5거래일 같은 매매 연속 손실(실전 2건↑·모의 3건↑).
6. **출력** — `docs/journal/YYYY-MM-DD.md`(문서 문체 '~임/~됨/~함', 끝에 약어 풀이), 텔레그램은 짧은 요약 + 실전 차트 사진. 매매 없는 날도 시장 판정·못 산 신호는 보냄.
7. **주간** — `docs/journal/week-YYYY-Www.md`: 날마다 표, 실전·모의·가상 매매별 성적, 반복 문제(직접 매도·손절·손절선 접근·놓친 +5%·연속 손실) 횟수와 사례.

## 2. 명령
```
.venv\Scripts\python.exe -m kiwoom_trading.execution.journal [YYYYMMDD]          # 그날 일지 + 텔레그램 요약 미리 보기 (전송 안 함)
.venv\Scripts\python.exe -m kiwoom_trading.execution.journal YYYYMMDD --send     # 전송까지
.venv\Scripts\python.exe -m kiwoom_trading.execution.journal --week [YYYYMMDD]   # 그 주 월~지정일 주간 묶음
.venv\Scripts\python.exe -m kiwoom_trading.execution.journal --since 20261016 --until 20261105   # 여러 날 파일만 (+ 주간), 전송 없음
```
- 매일 20:00 `ingestion/run_daily_update.py` 가 모의 타점 차트 다음에 `journal.run_daily` 로 작성·전송(금요일엔 주간도). 실패해도 업데이트는 계속.
- screener DB 는 본 DB 를 read_only 로 열고, 잠겨 있으면(장중 스캐너) `data/screener_snapshot.duckdb` 로 대신함. `--db` 로 지정 가능.
- 1분봉: `daily_ohlcv.duckdb` minute_ohlcv(감시 종목 KRX·AL) → `minute_history.duckdb`(AL 대금 상위 500). 정규장 종가는 15:30 까지 마지막 1분봉 → `daily_regular` → 통합 일봉(애프터 포함, 표시함).
- 2026-10-16 ~ 11-05 거래일 15일치를 처음 한꺼번에 만듦(실전은 10-26 부터, 그 전 날은 모의만).

## 3. 복기 노트 쓰는 순서 (`docs/journal/review-YYYY-MM-DD.md`)
1. **매매 한 건씩**: 왜 샀나(포착 이유) → 그때 시장(판정·큰 흐름·간밤 미국) → 결과(손익·차트) → 규칙대로였나(직접 매도면 '규칙대로였으면'과 비교) → 배운 점.
2. **매매별 성적표**: 실전·모의·가상 건수·이긴 수·합계 손익 (승률 말고 합계·기대값·손익비·낙폭으로 봄).
3. **반복 문제**: 주간 표의 반복 문제, 못 산 신호가 계속 좋거나(놓친 기회) 나쁜지(피한 손실), 같은 매매 연속 손실.
4. **개선 후보**: 문제마다 '매수 전에 알 수 있던 정보'로 만든 규칙 후보만 (미래 정보 금지 — 스킬 backtest-rules).
5. **판단**: 후보는 1년 백테스트 + **10만 계좌 1년·최근 3달 시뮬**로 판단. 건당 통계만으로 매매를 넣고 빼지 않음(10-31 4️⃣ 잘못 뺀 일).
6. **사용자 결정**: 결과 표와 추천을 보여 주고 사용자가 고름.
7. **반영**: 결정된 규칙은 해당 매매 스킬(stock-selection·buy-signals·trading-ops·매매법별 스킬)과 코드에 넣고, 복기 노트에 '반영: PR #…' 를 적음.

## 4. 주의점
- **실전 상황은 계좌 체결·잔고를 먼저 확인** (kt00018 잔고·ka10076 체결). real_trades 기록과 계좌가 다르면 계좌가 맞음 — 일지는 표 기록을 그대로 옮길 뿐임.
- **직접 매도는 장부를 닫고**(real_trades status='closed', reason '직접 매도 (사용자 HH:MM)') 일지에서 '규칙대로였으면'과 비교. 장부가 열린 채면 스캐너가 다음 날 또 팔려고 함.
- **하루 사례로 규칙을 만들지 않음** — 일지·복기는 후보를 찾는 곳이고, 규칙은 1년 검증과 계좌 시뮬로 정함.
- 실패한 규칙을 '가상 기록'으로 남기자고 하지 말고 매수 신호로 쓸 형태를 찾음.
- 매매 번호 옆에는 항상 매매 이름 (1️⃣ 상승장 장 초, 5️⃣ 약세장 인버스, 📕 홍인기 상한가 풀림, 🪜 애프터 정배열 …). 차트 그림 제목엔 이모지를 넣지 않음(글꼴 깨짐 → '1번 상승장 장 초').
- 문서는 '~임/~됨/~함' 문체, 페이지 끝 약어 풀이(API·IP·DB·URL·HTTP·CS·OTA 제외, 처음 나온 순서).

## 5. 남은 한계
- 포착 이유는 `buy_signals` 에 있는 신호만 찾음. 📕 는 가상 장부 note, 그 밖에 기록이 없으면 비움.
- '실전 안 삼' 로그 줄에는 종목코드가 없어 그날 buy_signals·stocks 이름으로 코드를 찾음 — 이름이 같은 종목이 있으면 틀릴 수 있음.
- 그날 1분봉이 없는 종목(감시 목록 밖·대금 상위 500 밖, 예: 신규 상장 스팩)은 차트·'규칙대로였으면'·손절선 접근을 못 셈.
- 다음 날 시가가 필요한 비교(🌙·4️⃣ 못 산 신호, 직접 매도 뒤 다음 날 매도)는 다음 날 20:00 자료가 쌓여야 채워짐 — 그날 밤 일지는 '그날 종가 기준'으로 적음. 지난 날 일지를 다시 만들면 채워짐.
